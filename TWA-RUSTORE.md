# Подготовка «Татарча» к TWA и RuStore

Дата проверки: 10 сентября 2026 года. Подготовлена веб-часть и инструменты привязки. Android-проект, подписанный APK/AAB и публикация ещё не созданы: пока нет окончательного домена, package name и сертификата подписи.

## Что уже готово

- PWA с названием, постоянным `id`, `start_url`, `scope`, русской локалью и категорией education.
- PNG-иконки 192×192, 512×512 и отдельная maskable-иконка с непрозрачным фоном и запасом под обрезку Android. Её исходник: `twa/maskable-icon.svg`.
- Service worker и локальные шрифты: после первой успешной загрузки приложение и встроенные фразы доступны офлайн.
- Vercel отдаёт manifest и Digital Asset Links с явным Content-Type. Service worker не подменяет `/.well-known/` HTML-страницей приложения.
- `twa/release.config.json` для публичных параметров, `npm run twa:prepare` для создания Digital Asset Links и `npm run twa:check -- --remote` для проверки опубликованных файлов.
- Ключи подписи, APK/AAB, локальные настройки SDK и результаты Android-сборки исключены из Git.
- В приложении нет регистрации, платежей, рекламы, push-уведомлений и собственного сервера синхронизации. RuStore SDK для текущих функций добавлять не требуется.

## Чего не хватает до релиза

| Что | Что нужно сделать |
| --- | --- |
| Постоянный домен | Выбрать принадлежащий вам HTTPS-origin. Preview-адрес не использовать как постоянный адрес релиза. Домен должен быть публичным, без пароля Vercel и редиректа на другой origin. |
| Package name | Выбрать окончательный идентификатор, например `ru.company.tatarcha`. Это пример, а не выбранное имя. Использовать одно имя в Bubblewrap, RuStore и assetlinks. |
| Release-подпись | Создать либо выбрать keystore и alias. Хранить резервную копию и пароли отдельно от репозитория. Для обновлений требуется та же подпись. |
| SHA-256 | Получить отпечаток сертификата, которым подписан APK, устанавливаемый пользователем. Это не SHA-256 файла APK и не debug-сертификат. |
| Android-проект | Создать через Bubblewrap после публикации PWA на постоянном домене. В репозитории пока только подготовка, не готовая Android-обёртка. |
| Android-сборка | Настроить JDK/SDK через мастер Bubblewrap, принять лицензии SDK и собрать release APK. Проверить фактические minSdk/targetSdk и совместимость с текущими требованиями RuStore. |
| Физическое устройство | Проверить установленный APK и работу на выбранных Android-браузерах, включая устройство без Google Play Services. Наличие RuStore само по себе не гарантирует наличие TWA-браузера. |
| Аккаунт RuStore | Зарегистрировать и подтвердить профиль разработчика, заполнить юридические/контактные данные. |
| Карточка магазина | Подготовить иконку, реальные скриншоты Android-приложения, описание, категорию, возрастную маркировку и контакты поддержки. Точные форматы/лимиты проверить в текущей консоли RuStore. |
| Политика конфиденциальности | Добавить имя владельца, контакт и описание реального хостинга; опубликовать документ на постоянном HTTPS-URL и сделать доступным из приложения. Ниже приведены факты для подготовки текста. |
| Права на контент | Подтвердить права на существующие импортированные фразы, иллюстрации и название; проверить лицензии зависимостей и шрифтов. Для 1 000 фраз желательна вычитка преподавателем. |
| Публикация | Загрузить подписанный файл в RuStore и пройти модерацию. Техническая работоспособность TWA не гарантирует одобрения магазина. |

## Порядок сборки

### 1. Опубликовать PWA

Из корня проекта:

```bash
npm ci
npm run build
```

Опубликовать `dist` на окончательном HTTPS-домене. Убедиться, что открываются `/`, `/manifest.webmanifest`, `/sw.js`, `/pwa-512x512.png`, `/pwa-maskable-512x512.png` и прямые ссылки `/study/group-a1-greetings`. Локальная сборка не обновляет production сама по себе.

### 2. Создать Android-проект

Установить Bubblewrap по [официальной инструкции](https://github.com/GoogleChromeLabs/bubblewrap/blob/main/packages/cli/README.md). Мастер предлагает установить совместимые JDK и Android SDK. Зафиксировать использованную версию CLI в release-заметках.

```bash
npm install -g @bubblewrap/cli
bubblewrap --version
bubblewrap init --manifest=https://YOUR-DOMAIN/manifest.webmanifest --directory=android
```

`YOUR-DOMAIN` заменить реальным доменом. В мастере выбрать окончательный package name, название «Татарча», запуск `/`, основную и maskable-иконки из манифеста. Не включать уведомления, location, billing или другие неиспользуемые функции. Проверить итоговые разрешения AndroidManifest.

Keystore лучше расположить вне проекта. Пароли вводить интерактивно; не помещать их в команды, `twa-manifest.json`, Git или этот документ. Генерируемый `android/twa-manifest.json` и исходники можно хранить в Git после проверки отсутствия секретов. `bubblewrap update` перегенерирует Android-файлы, поэтому ручные изменения обёртки следует учитывать отдельно.

### 3. Собрать и проверить подпись

```bash
cd android
bubblewrap build
```

Ожидаемый результат — `app-release-signed.apk` и `app-release-bundle.aab`. Для первого релиза проще загрузить собственный подписанный APK; RuStore принимает APK и AAB. При выборе AAB предварительно настроить подпись в RuStore и выяснить сертификат APK, который магазин будет отдавать пользователям. [Публикация в RuStore](https://www.rustore.ru/help/developers/publishing-and-verifying-apps/app-publication), [подпись при загрузке AAB](https://www.rustore.ru/help/work-with-rustore-api/api-upload-publication-app/apk-file-upload/file-upload-aab).

Из Android SDK Build Tools выполнить (путь к версии Build Tools подставить свой):

```bash
apksigner verify --verbose --print-certs app-release-signed.apk
```

Альтернатива для чтения сертификата keystore:

```bash
keytool -list -v -keystore /ABSOLUTE/PATH/release.jks -alias YOUR_ALIAS
```

Нужен SHA-256 сертификата. Если `apksigner` напечатал его без разделителей, представить как 32 пары HEX через `:`. Не заменять им SHA-1.

### 4. Связать сайт с APK

В корне проекта заполнить `twa/release.config.json`:

```json
{
  "origin": "https://YOUR-DOMAIN",
  "packageName": "ru.company.tatarcha",
  "sha256CertFingerprints": ["ACTUAL_SHA256_CERTIFICATE_FINGERPRINT"]
}
```

Значения выше — шаблоны. SHA-256 и package name публичны; закрытый ключ сюда не добавлять. При нескольких действительных release-сертификатах указать все нужные отпечатки, сохраняя поддержку установленных версий.

```bash
npm run twa:prepare
npm run twa:check
npm run build
```

Генератор создаст `public/.well-known/assetlinks.json`. Файл включить в Git и повторно опубликовать PWA. При добавлении приложения на домен с уже существующими Digital Asset Links нужно сохранить также прежние привязки; генератор не затирает чужие package name.

```bash
npm run twa:check -- --remote
```

Проверка требует `200 application/json` без редиректов и сверяет содержимое. Пустые настройки намеренно завершают команды ошибкой: приложение не должно считаться готовым с фиктивной подписью. Пока файл не создан, URL assetlinks не готов к проверке.

TWA проверяет соответствие сайта и Android-подписи. При ошибке может открыться вкладка с браузерной панелью. Подробности: [официальное руководство Chrome по TWA](https://developer.chrome.com/docs/android/trusted-web-activity/quick-start).

### 5. Проверить установленную сборку

```bash
adb install -r android/app-release-signed.apk
```

- Первый запуск онлайн: нет адресной строки, верны название и иконка, доступны 20 тем по 50 фраз.
- Свайпы в обе стороны, показ перевода, переключатель русский → татарский, отмена ответа, клавиатура и системная кнопка «Назад».
- Закрытие/повторный запуск: собственные группы и прогресс сохранились.
- После прогрева кэша: включить авиарежим, перезапустить, открыть несколько тем. Первый запуск без сети отдельно: кэша ещё нет, TWA не содержит весь сайт внутри APK.
- Проверить крупный шрифт Android, небольшой экран, поворот, вырезы и системные панели, светлую/тёмную системную тему.
- Проверить штатный fallback на устройстве без совместимого TWA-браузера. Если требуется полностью независимая от браузера/первого подключения работа, нужна другая обёртка, например Capacitor с локальными ресурсами.
- Проверить обновление APK с теми же package name и подписью, увеличив `versionCode`, а затем обновление веб-части без прерывания занятия.
- После загрузки в магазин проверить сборку из RuStore, особенно если используется AAB и подпись магазина.

## Факты для политики конфиденциальности

Это основа для документа владельца, а не готовая опубликованная политика:

- Приложение сохраняет свои карточки, группы, скрытые карточки и учебный прогресс в localStorage браузера, обслуживающего TWA.
- Учётных записей и серверной синхронизации в текущем коде нет. Очистка данных браузера/сайта может удалить прогресс; смена браузера или домена не переносит его автоматически. Удаление Android-обёртки не обязательно удаляет данные браузера.
- Сайт загружается по сети: хостинг/CDN получает обычные HTTP-запросы, в том числе IP и технические сведения. Нельзя обещать отсутствие любой передачи данных. Указать фактического провайдера и его правила обработки/хранения логов.
- Шрифты поставляются локально. В текущем коде нет аналитики, рекламных SDK, доступа к камере, микрофону, контактам или геолокации.
- Требуются имя/наименование владельца, контакт по вопросам данных, дата действия и доступный пользователю способ удаления локальных данных. Сейчас кнопка сброса в интерфейсе появляется только в безопасном режиме; для обычного режима можно описать очистку данных сайта в браузере или отдельно добавить явную кнопку удаления.

## Черновик карточки RuStore

Название: **Татарча — карточки**.

Краткое описание: «Татарский для начинающих: 1 000 фраз по 20 повседневным темам».

Описание: «Учите татарские фразы для знакомства, семьи, покупок, поездок и других повседневных ситуаций. Выберите тему, вспомните перевод и отметьте, знаете ли фразу. Переключайте направление перевода, добавляйте собственные карточки и группы. Прогресс сохраняется на устройстве. После первой загрузки приложение работает без интернета».

Категория-кандидат: образование. Скриншоты: главная с темами, открытая карточка с переводом, обратное направление, группы, поиск. Возрастную маркировку и декларации данных заполнить по фактическому контенту и требованиям консоли; не угадывать юридические данные или контакты.

## Граница готовности

`npm run build` и веб-тесты подтверждают только веб-часть. До выбора домена/подписи, создания Android-проекта и проверки подписанного APK на устройстве готовность TWA к публикации не подтверждена. Публикация и модерация выполняются отдельно.
